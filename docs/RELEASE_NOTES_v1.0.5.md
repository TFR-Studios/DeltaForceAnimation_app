# v1.0.5 —— 编辑实时可见,不再每改一步就闪一下

这一版改的是**编辑时的观看体验**。以前每改一个文字、一个颜色、一次不透明度,应用都会把整段动画
销毁重建:先等 250ms 防抖,重建期间画布被隐藏(大多动画空白 1~2 帧,核电站那套约 140ms),
重建完再触发一次 300ms 的「舞台落定」——整块画布从透明 + 3px 模糊淡入,还带一条扫描线。
所以改一步就闪一下,改一步要等半秒多才看到结果。

现在:

- **重建用双缓冲换屏** —— 新实例先在一个隐藏宿主里建好,在同一帧画好之后才整层换上,旧实例这一刻
  才销毁。画面全程有内容,没有空白帧;
- **改字当帧就能看到** —— 文字编辑直接把新内容写进正在显示的动画实例,再强制重画当前帧,
  实测 3~13ms 生效(以前约 300ms + 300ms 淡入);
- **拖动时连续更新** —— 取色器、不透明度滑杆、主题色、弹窗颜色改成节流重建,拖动过程中画面持续
  跟着变,而不是松手后才更新一次;
- **编辑不再演「舞台落定」** —— 那 300ms 的淡入/模糊/扫描线只留给「换了一套动画」这一件事。

## 这一版改了什么

### 编辑时不再闪

- **双缓冲换屏**:新动画实例先在隐藏宿主里构建、在同一帧画好,才整层换上;旧实例这时才销毁。
  换上前后是同一帧,所以看不到空白,也看不到画面跳变。
- **编辑期的重建不再触发「舞台落定」**:以前每次重建都走一遍整块画布的 300ms 淡入 + 模糊,
  这才是「每改一步闪一下」最刺眼的部分。换动画时仍然保留这个落定动画。
- **主动画重建不再顺手重建弹窗叠加层**:弹窗有自己的数据,以前每次改主动画都跟着重建一次,
  开着弹窗时叠加层会闪。现在只在渲染器变化或弹窗数据真的换了才重建。

### 改字当帧可见

- 文字编辑走一条「即时通道」:直接更新正在显示实例里对应的文字层,并强制重画当前帧。
  实测从敲键到画面变化 **3~13ms**(一帧内);完整重建延后 180ms 提交,把底框宽度、字形表
  这些必须重建才能对齐的东西补上。
- **带字形表(chars)的动画有保护**:表外字不会在即时通道里被画成空路径(那会看起来像文字消失),
  第一次改表外字会等这次提交重建(约 200ms,一次);字表丢掉之后就一直走浏览器字体,之后每个字都是实时的。
- **弹窗叠加层的文字同样即时**:改「弹窗图层」里的文字也是当帧可见,并顺带修掉叠加层重建时的闪。

### 拖动时连续更新

- 取色器、不透明度滑杆、主题颜色、弹窗颜色:从「停手 250ms 后才重建一次」改成节流重建
  (80ms 起,并会按当前动画的重建耗时自适应),拖动过程中画面持续跟着变。
- **图标居中微调**的 ±px 按钮也改成立即写数据 + 节流重建,连点能立刻看到位移。
- **帧号、播放/暂停状态在重建前后保持不变**:暂停在第 100 帧改字,改完仍然是第 100 帧暂停。

### 仓库维护

- `.gitignore` 补上 `/release-assets-check/`(发布自检时下载/解包出来的目录)。之前漏了这条,
  发布机器上会把几百 MB 的安装包产物误提交进仓库;这次也在发布前把本地一个含 391MB 产物的
  未推送提交清掉了,历史保持干净。

## 已知说明

- 黑潮爆破默认弹窗动画带 700 多张逐帧图,它的一次重建本身就要几百毫秒;拖动不透明度时更新频率会
  自适应降低(约一秒几次),但仍然是连续的、没有空白帧。
- 首次把「任务弹窗 / 地图标题 / 黑潮爆破 / 撤离点开启」这几套带字形表的动画改成表外字时,
  第一个字要等约 200ms 的提交重建;之后每个字都是实时的。
