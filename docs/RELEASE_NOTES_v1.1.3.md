## 这一版改了什么

### 第 10 套动画:物品搜索动画(#010)

画面由 195 帧「放大镜」逐帧序列(翻页书式播放)、一张物品图标、一行物品名「非洲之心」、
三条物品颜色叠加(色块 / 辉光 / 发光)与一条渐变底框组成:

- **图标可换**:「图标选择」里可以切素材目录里的图标,也可以上传自己的图(任意长宽比等比完整显示、不裁切);
- **文字可改**:「文字图层」改物品名与文字颜色,底框会跟着文字宽度走;
- **颜色可调**:「形状图层」改物品颜色层与底框的颜色 / 不透明度;物品颜色由三条叠加层 + alpha 遮罩切出物品轮廓;
- **没有「动画时长」区块**:放大镜序列是每帧一条单帧图层,搬关键帧等于把翻页书撕开,所以时间轴按 AE 导出原样呈现(237 帧 ≈ 3.95s);
- 修掉一个会让编辑失效的底层问题:预合成 `comp_0` / `comp_1` / `comp_2` 的图层编号以前会互相撞号,
  侧栏改物品名 / 改颜色时会静默写到另一份合成的同号图层上;现在每份预合成各占一段独立编号,改哪层就是哪层。

### 手机端导出:核电站功率动画不再掉字体

- **现象**:手机上导出核电站功率动画,成片里的五个数字位和「核心反应堆功率」变成了系统默认字体(或干脆少了字形);
  预览完全正常,其它动画的导出也正常。
- **原因**:这套动画含「共用轨道遮罩」,导出必须走 SVG 逐帧光栅化;它的文字是真实 `<text>`,字形完全取决于字体。
  每帧的 SVG 会被序列化成独立文档、再用 `<img>` 加载 —— 这个文档里 `blob:` / `http(s)` 字体都会被浏览器静默丢弃,
  只有 `data:` 资源进得去。桌面端因为本机装了「战术体 / 战术粗体」(内部 family 名就是 ProjectD Type / ProjectD Type Curve),
  字体没加载、回退到系统字体后画出来一模一样,所以这个问题一直没暴露;手机没装这套字体就露馅了。
- **修复**:导出时把克隆帧里的每个 `<text>` 用**站点自己注册的字体**(含 FontFace,手机上就是随应用打包的那份)
  画成一张小位图,替换成 `<image>`。这样既不依赖手机装没装字体,也不用往每帧里塞几 MB 字体:
  一套动画只有几十个字形,按「字 + 字体 + 字号 + 颜色」缓存,整段导出每帧只做几十次 DOM 替换。
- **顺带修复**:任务弹窗 / 地图标题等动画在改字之后(字形表 `chars` 被丢掉)也会走同一条光栅化路径,
  以前同样会掉字体,这次一起解决。
- 实测(核电站第 200 帧,模拟手机只有文档字体):与原字体基准逐字对比 **IoU 0.96、墨量 98.4%、重心偏移 <0.3px**;
  每帧的文字替换约 **3~7ms**,不会明显拖慢导出。

### 素材与文档

- 核电站功率动画的「模糊效果」叠加序列(`99999` 那组 PNG)素材更新一版,红光过渡更连贯;
- 文档同步到「十套动画」,并改正了兼容导出一节里关于字体内联方式的错误说法。

## 已知说明

- Windows 产物没有代码签名,首次运行会有 SmartScreen 提示;安装版支持应用内更新,便携版与手机走「前往下载」。
